# Outer sandbox wrapper (portable layer)

Wrap **any** agent in an OS sandbox whose protected set comes from the reversibility
model. Catches shell writes and works regardless of the agent's internals — the half
a per-agent tool-level gate can't do.

`srt-outer.json` uses the placeholder `"PROJ"` for the project directory, so don't pass
it to `srt` directly. Run through `srt-log.mjs` (below), which substitutes it, or
substitute it yourself:

```sh
sed "s#\"PROJ\"#\"$PWD\"#" experiments/wrapper/srt-outer.json > /path/outside/project/srt.json
srt -s /path/outside/project/srt.json -- <agent> ...
```

The policy allows no network and writes only inside the project (not `/tmp`, which
the checkpoint doesn't cover). A real agent needs its model provider's domain in
`allowedDomains`, and usually its own config and credential paths readable; add those
per agent. Running real agents under it hasn't been recorded here yet.

## Generated from the policy, not hand-written

`srt-outer.json` is **generated by Lean** from the outer policy in
`FinalSay/SrtConfig.lean` (run-later names, protected reads, network):

```sh
./.lake/build/bin/finalsay srt-config experiments/wrapper/srt-outer.json
```

Don't edit the JSON by hand; change `defaultOuter` and regenerate. Lean proves the
generator is faithful: the rendered globs deny exactly the paths with a segment matching
`defaultOuter.runLater` (`generated_covers`, `generated_exact`), at any depth and under
ASCII case folding (`nested_case_variant_denied`). That says nothing about whether the
list is complete. What Lean can't prove is that `srt`
enforces `**/name` that way; that's the trusted assumption `probe.sh` checks: every run-later name at the root, nested, and in upper case, plus `/tmp`, `$HOME` and an ordinary write (42/42 on macOS; not yet run on Linux).

## Log and stop: `srt-log.mjs`

Runs a command under the generated policy using `srt` as a library. The OS **stops**
every denied write, read or connection; the wrapper **logs** each one as a JSON line
naming the kind of boundary crossing and the rule that stopped it
(`run-later-write` / `**/.codex`, `write-outside-project` / `allowWrite`,
`read-denied` / `denyRead`, `network-egress` / `network`). The run-later list is read
from the generated settings, so there is one list. On Linux, srt's seccomp observer
covers this too (untested here).

Tested live on macOS. Every crossing was stopped and logged with its rule.
Two caveats:
- srt's macOS monitor keeps only the first violation in each chunk of `log stream`
  output (upstream #806), so a burst of denials can be logged as one. Blocking is
  unaffected.
- System-query denials (`sysctl-read`, `mach-lookup`, ...) are filtered as noise.

```sh
SRT_LIB=$(nix build .#sandbox-runtime --print-out-paths --no-link)/lib/node_modules/@anthropic-ai/sandbox-runtime/dist/index.js \
  node experiments/wrapper/srt-log.mjs --settings experiments/wrapper/srt-outer.json --log denials.jsonl -- <agent...>
```

## Use depth-independent globs
`srt`'s `denyWrite` is **root-relative** by default: `".codex"` only denies
`<workspace>/.codex`, not a **nested** `sub/.codex`. Use **depth-independent globs** instead:

    "denyWrite": ["**/.git", "**/.codex", "**/.cursor", "**/.agents", ...]

With `**/`, srt denies the path at any depth, and the `.GIT` case variant too.
`srt-outer.json` here does this for every run-later config dir.

## Inner + outer (both)
- **Outer (this):** every tool incl. shell; depth-independent; network egress; `$HOME`.
  Allow/deny only — no "ask", no taint, no compensation.
- **Inner (the gate, e.g. examples/pi):** typed tools only, but adds ask-a-human for
  irreversible actions, taint/trifecta, compensation, and normalized classification.

They cover each other's gaps. The one tension: the outer layer is blunt (it *denies*),
so it also blocks a *legitimate* edit to those dirs. Scope the outer deny to the
truly-never-allowed set and let the inner gate handle the "ask" cases, or route
legitimate edits through a gate running outside the sandbox.
